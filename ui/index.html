Google A2A vs Anthropic MCP: Protocol Comparison

Why do both A2A and MCP use JSON-RPC 2.0?
JSON-RPC 2.0 is an open, lightweight, transport-agnostic standard that provides request/response correlation (id), structured error codes (code, message), and optional batching. However, A2A and MCP operate at fundamentally different architectural layers:

Feature Anthropic MCP (Model Context Protocol) Google A2A (Agent2Agent Protocol)
Primary Relationship Host-to-Tool / Client-to-Resource (1:N tools) Agent-to-Agent / Peer-to-Peer (Collaborative federation)
Autonomous Reasoning ❌ No reasoning on server. Tool servers are passive functions returning data. ✅ Both sides have cognitive loops. The recipient agent runs its own models, planners, and tools.
Task Granularity Micro-operations: tools/call, resources/read, prompts/get Macro-missions: message/send, tasks/create, tasks/get
Boundary Opacity Transparent: Client inspects every function signature and raw output. Opaque: Internal prompts, weights, and tools are hidden; only deliverable Artifacts are returned.
Discovery Manifest Tool schemas via tools/list Agent Card at /.well-known/agent-card.json declaring skills, capabilities, and TOS
Cross-Framework Interop Standardizes tool interfaces for an LLM Connects heterogeneous agents (e.g. Google ADK $\leftrightarrow$ LangChain)
Summary: Use MCP when your agent needs to connect to local tools (file system, database driver, git CLI). Use A2A when your agent needs to collaborate with another specialized, autonomous agent across team or organizational boundaries.
